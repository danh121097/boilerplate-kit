# React Native + TypeScript Standards

## TypeScript config

- `strict: true` — all strict checks enabled.
- `noUncheckedIndexedAccess: true` — array/object index access returns `T | undefined`.
- No `any` without an explicit justification comment.
- Module resolution: `Node` (React Native / Metro-compatible).

## Screen component structure

```tsx
// 1. imports — named value, then type, then side-effect
import { useEffect } from "react";
import { View, Text } from "react-native";
import type { NativeStackScreenProps } from "@react-navigation/native-stack";

// 2. interface/type declarations above the component
interface Props extends NativeStackScreenProps<RootStackParamList, "ProfileScreen"> {
  userId?: string;
}

// 3. named export (no default export for screens)
export function ProfileScreen({ navigation, route }: Props) {
  // 4. hooks first
  const { t } = useTranslation();
  const { data: user } = useUsersListQuery();

  // 5. effects
  useEffect(() => {
    navigation.setOptions({ title: t("screens.profile") });
  }, [navigation, t]);

  // 6. derived values
  const username = user?.name ?? t("unknown");

  // 7. handlers
  function handleLogout() {
    // ... logout logic
  }

  // 8. render
  return (
    <View className="flex-1 bg-white">
      <Text className="text-lg font-bold">{username}</Text>
    </View>
  );
}
```

## UI Primitive components

All UI primitives (Button, Input, Card, Text) are hand-written in `src/components/ui/`
with NativeWind `className` props:

```tsx
interface ButtonProps extends Pressable {
  label: string;
  variant?: "primary" | "secondary";
}

export const Button = forwardRef<View, ButtonProps>(
  ({ label, variant = "primary", className, ...props }, ref) => (
    <Pressable
      ref={ref}
      className={cn(
        "rounded px-4 py-2",
        variant === "primary" && "bg-blue-600",
        className
      )}
      {...props}
    >
      <Text className="text-white font-semibold">{label}</Text>
    </Pressable>
  )
);
Button.displayName = "Button";
```

## Custom Hooks

- Live in `src/hooks/` with `useXxx.ts` naming (camelCase, matching hook name).
- Service query/mutation hooks are generated by `defineQuery`/`defineMutation`
  in the service layer — do not duplicate them in `src/hooks/`.

## Service queries in screens

```tsx
// Async SecureStore — all token reads return promises
const { data, isLoading, error } = useUsersListQuery();
```

## Stores (Zustand)

```tsx
// Explicit import — never rely on auto-import
import { useAuthStore } from "@/stores/auth";
const { token, setToken } = useAuthStore();
```

## Async token storage

All token reads/writes are async (via `expo-secure-store`). Promises must be awaited:

```tsx
// ❌ Wrong: sync access
const token = SecureStore.getItem("token");

// ✅ Correct: async await
const token = await SecureStore.getItemAsync("token");
```

## i18n

```tsx
const { t, i18n } = useTranslation();
// interpolation uses double-braces: t("users.error", { message: "..." })
```

## File size

Target ≤ 200 LOC per file. Split early by extracting:
- Style/variant definitions to a separate `-variants.ts`
- Business logic to a service or hook
- Sub-components to their own file

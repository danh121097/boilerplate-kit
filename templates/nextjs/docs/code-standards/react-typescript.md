# React + TypeScript Standards

## TypeScript config

- `strict: true` — all strict checks enabled, plus `noUncheckedIndexedAccess`,
  `noFallthroughCasesInSwitch` and `verbatimModuleSyntax` (use `import type` for
  types; indexed access returns `T | undefined`).
- No `any` without an explicit justification comment.
- Module resolution: `bundler`; `@/*` maps to `./src/*`.

## Server vs client components

Components are Server Components by default. Add `"use client"` at the top of a
file only when it uses hooks, browser APIs (`window`, `localStorage`), event
handlers or client-only libraries (react-i18next hooks, Zustand). Keep the
client part small: a server `page.tsx` prefetches data and renders a client
island (`app/users/page.tsx` → `users-list-client.tsx`). Server-only code lives
in `src/server/` and must not be imported from client files.

## Component structure

```tsx
"use client";

// 1. imports — named value, then type, then default, then side-effect
import { useState } from "react";
import type { HTMLAttributes } from "react";

// 2. interface/type declarations above the component
interface Props extends HTMLAttributes<HTMLDivElement> {
  label: string;
  error?: string;
}

// 3. named export (pages and layouts are the default-export exception)
export function MyComponent({ label, error, ...props }: Props) {
  // 4. hooks and leading declarations (ordered by local/sort-leading-declarations)
  const [open, setOpen] = useState(false);

  // 5. derived values
  const hasError = Boolean(error);

  // 6. handlers
  function handleClick() { setOpen((v) => !v); }

  // 7. render
  return <div {...props}>{label}</div>;
}
```

## forwardRef pattern

UI primitives (`Button`, `Input`, `FormField`) use `forwardRef` so
react-hook-form can attach refs:

```tsx
export const Input = forwardRef<HTMLInputElement, InputProps>(
  ({ className, ...props }, ref) => <input ref={ref} className={cn("...", className)} {...props} />,
);
Input.displayName = "Input";
```

## Hooks

- Custom hooks live in `src/hooks/` with `useXxx.ts` naming.
- Service query/mutation hooks are generated by `defineQuery`/`defineMutation`
  in the service layer — do not duplicate them in `src/hooks/`.

```tsx
const { data, isLoading, error } = useUsersListQuery();
```

## Stores

```tsx
// Explicit import — never rely on global/auto-import
import { useCounterStore } from "@/stores/counter";
const { count, increment } = useCounterStore();
```

## Forms and validation

Forms use `react-hook-form` with `zodResolver` and zod 4 idioms (`z.email()`).
Schema messages are i18n keys, translated where they render:

```tsx
const schema = z.object({
  email: z.email("validation.email"),
  password: z.string().min(8, "validation.password_min"),
});
// error={errors.email?.message && t(errors.email.message)}
```

Every field goes through `FormField` (label + `htmlFor`/`id`).

## i18n

```tsx
const { t } = useTranslation();
// interpolation uses double-braces: t("users.error", { message: "..." })
```

## File size

Target ≤ 200 LOC per file. Split early by extracting:
- Variant/style definitions to a separate `-variants.ts`
- Business logic to a service or hook
- Sub-components to their own file

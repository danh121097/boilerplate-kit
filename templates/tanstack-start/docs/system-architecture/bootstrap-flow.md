# Bootstrap Flow

TanStack Start generates the client and server entries from virtual modules; both
call the `getRouter()` factory in `src/router.tsx`.

```
getRouter()                              once per SSR request, once in the browser
  1. initServices()                      browser only: axios baseURLs + interceptors
  2. makeQueryClient()                   fresh QueryClient (staleTime 60_000)
  3. initI18n()                          locale from the LANGUAGE cookie (server and client)
  4. createRouter({ routeTree, context: { queryClient } })
  5. setupRouterSsrQueryIntegration()    dehydrate on the server, hydrate + provider on the client

routes/__root.tsx  RootLayout            HTML document shell, nav, locale toggle,
                                         session-unavailable banner, session effects
  └── <Outlet />                         matched route (notFoundComponent when none)
```

## Key constraints

- `initServices()` must run before any `Api` instance makes a request, because it
  calls `Api.setBaseURL()` and `Api.registerInterceptors()`. It is skipped on the
  server: server functions fetch without the client service layer.
- `initI18n()` reads the locale cookie, so SSR renders the right language on the
  first paint.
- Session subscriptions (cache reset, expiry redirect, cross-tab sync) are effects
  in `__root.tsx`, not in `getRouter()`, which re-runs on HMR.
- `routeTree.gen.ts` is auto-generated by the `@tanstack/router-plugin/vite` Vite
  plugin from the file-based routes in `src/routes/`. It is committed as a
  cold-typecheck stub and regenerated on every `pnpm dev` / `pnpm build`.
